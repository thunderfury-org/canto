# Web Studio 交互范式、视觉层级与领域数据分层

规范 Web Studio 的交互布局模式（Master-Row + Drawer、卡片网格下钻）、视觉操作层级（单一 Primary 保存）以及前端领域计算纯函数边界（The Pure Seam）。颜色条款由 [ADR 0017](0017-console-surface-charcoal-and-copper.md) 取代。

## 背景

随着 Web Studio 演进为支持完整的 sing-box 配置编排（DNS 服务器与分流、入站与端点、路由流水线网格、两层出站体系与节点组正则占位符、多源规则集），界面复杂度与状态量急剧上升：

1. **交互膨胀与上下文迷失**：早期尝试在列表中就地内联展开表单，导致列表垂直长度过大，移动端挤压严重，用户在编辑某一项时极易丢失对整体规则拓扑的全局认知。
2. **视觉噪音与焦点争抢**：缺乏统一的操作优先级定义时，界面容易出现多个高饱和度实心按钮并存、色彩滥用等问题，弱化了核心持久化保存入口。
3. **视图与逻辑耦合风险**：若在 Svelte 组件内部直接做复杂 JSON 遍历、字段类型回退与语法清洗，在后续 UI 样式调整或响应式适配时极易误伤 sing-box 配置语义，产生隐蔽的配置退化。

## 决定

1. **按数据本质选择交互形态（Form Follows Function）**：
   - **深层多字段配置（Deep Pipeline）**（DNS 服务器与分流、入站与端点、路由分流规则、订阅）：统一采用 **Master-Row + Drawer（紧凑主行 + 侧边抽屉）**。单行紧凑展示高频只读特征（标签、类型、走向胶囊及操作栏），次级编辑收敛至右侧抽屉（桌面端固定 `w-[28rem]`，移动端全屏，支持 ESC 与遮罩退出），防止长表单撑爆视口。
   - **跨条目拓扑对照（Mapping Matrix）**（出站策略组）：采用 **紧凑表格（Compact Table）** 并支持上下移动排序。用户需一屏横向比对所有业务策略的分流出口，避免使用排他性抽屉破坏全局对照心智。
   - **即时输入调试与大结果集（Live Debugger）**（节点分组与正则调试）：采用 **Master-Row + Accordion（紧凑主行 + 就地全宽折叠）**。未展开时保持 44px 紧凑主行，展开后独占全宽水平平铺展示数十上百个命中节点的 Tag 徽章流。
   - **海量目录检视（Mass Catalog, 1000+）**（规则集全库浏览）：采用 **宽幅弹窗（Wide Modal）**，提供 A-Z 索引与网格多列过滤。

2. **顶层宏观视图采用单列主行与下钻导航（Master-Row Index & Drill-down）**：
   - 配置模板采用统一单列主行列表页（Index），舒展展示指标胶囊、用途说明、关联订阅与未保存草稿徽标，避免多列网格挤压文字；
   - 订阅采用紧凑主行加右侧抽屉，不另开详情页。抽屉固定标题，中间是订阅和绑定，底栏放重置、删除、放弃和保存。编译结果用链接查看。显式保存；与配置模板不同，第一次保存前不发布。
   - 点击卡片下钻进入独立全宽编辑详情页（Detail），顶部常驻返回链路、就地可编辑元数据与单行水平平滑 Tab 栏，废除固宽侧边栏对编辑宽度的挤压。

3. **草稿暂存与显式保存契约（Drafting vs. Explicit Save）**：
   - 编辑抽屉与表单在内存中维护独立 Draft，仅在用户点击抽屉确认或页头主保存时显式写回 Store 和后端。
   - 彻底杜绝输入过程中的无感全量自动写入，防止未完成的草稿或错误输入被意外持久化并分发给网关。

4. **视觉层级与操作规范**：
   - **单一实心主操作**：整个视口或抽屉内严格只保留一个实心 `btn-primary`，明确指示最终持久化保存。色值见 [ADR 0017](0017-console-surface-charcoal-and-copper.md)。
   - **次级操作幽灵化**：新建、克隆、展开、排序、取消等一律使用幽灵或边框按钮（`btn-secondary` / `btn-ghost`）。
   - **行内操作统一边框与图文自解释规范（Consistent Action Buttons & Borders）**：全站所有主列表项（配置模板、节点源、订阅、仪表盘）操作按钮一律统一采用带精致边框的 `btn-secondary` 变体，危险删除操作统一采用带边框的 `btn-secondary btn-danger`，消除边框有无的视觉割裂；按钮文字与图标全端保持完整自解释呈现（如 `[克隆]`、`[编辑]`、`[刷新]`、`[删除]`），严禁混用无边框幽灵态或在移动端出现有的带字有的不带字的割裂体验。
   - **破坏性操作防呆（Destructive Action Guards）**：删除模板、节点源、分组、策略组必须带二次确认防呆；若存在关联引用（如模板或节点源正被订阅引用），必须在确认弹窗中明示受影响的实体列表。
   - **语义化状态徽章**：直连与健康用 Emerald，阻断与拦截用 Rose，动态匹配与警告用 Amber。类型胶囊用炭灰。

5. **纯函数领域数据边界（The Pure Seam）**：
   - **Svelte 组件只做展示与事件触发**：Svelte 5 组件仅消费 Store 数据，严禁在组件内编写复杂的 JSON 校验与 sing-box 规则语法拼接。
   - **领域计算下沉纯函数**：所有配置规范化（`normalizeTemplateContent`）、草稿转换（`createDraft` / `applyDraft`）、占位符嗅探（`matchNodeTags`）与错误推导全部收敛于 `web/src/data/*.js` 纯函数模块中。
   - **单元测试强制锁定**：每个 `src/data/<module>.js` 必须在 `web/test/<module>.test.js` 中有对应的独立自动化测试。UI 样式重构不得破坏纯数据测试。

## 影响与收益

- **大幅降低后续功能开发耗时**：后续新增功能（如新型入站协议、策略组算法扩展）可直接套用既定的 Master-Row + Drawer 模板，无需反复设计交互架构。
- **多端响应式自然对齐**：移动端无需单独设计复杂流程，直接遵循主行紧凑流与全宽抽屉规范。
- **配置生成绝对健壮**：通过 Pure Seam 和 `node --test`，将样式重构与配置数据生成彻底物理隔离，保护生产端生成的 sing-box 配置零语法退化。
